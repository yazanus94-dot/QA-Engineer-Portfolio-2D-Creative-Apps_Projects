# BUG-001: Undo after "Clear" restores the wrong state

| Field | Value |
|---|---|
| Severity | High |
| Priority | P1 |
| Component | History / Clear |
| Environment | Sketchpad v1.0 with `?bugs=BUG-001`, Chrome (latest), Windows 11 |
| Related test case | TC-HIST-003 |
| Reproducibility | Always (5/5) |

## Preconditions
Blank canvas.

## Steps to reproduce
1. Draw rectangle A, then rectangle B (canvas shows 2 objects).
2. Click **Clear**. The canvas is empty.
3. Click **Undo**.

## Expected result
Both rectangles return (2 objects), the same state as before Clear.

## Actual result
Only rectangle A returns (1 object). Rectangle B is lost. Clear was never added to the history, so Undo reverted the last drawing instead.

## Impact
Users lose work. Clear is easy to click by mistake and the data cannot be recovered.

## Evidence / root-cause hint
Status bar shows "1 object" after Undo. `clear()` skips the snapshot push that `addShape()` performs.
